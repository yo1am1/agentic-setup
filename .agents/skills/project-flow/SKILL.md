# Project flow

Read [project guidance](../../README.md) and relevant [rules](../../rules/README.md).
Use brief planning and solo execution by default. Read the current host's STARTUP.md
if present; missing startup guidance means simple mode.

In simple mode, solve the requested task with core skills and available host tools.
Do not load optional procedures or register a native team merely because their
source files exist elsewhere in the repository.

Full mode makes [roles](../../agents/README.md) and optional procedures available;
it does not require them. Use SpecsMD for substantial durable requirements, a team
for useful independent work when delegation is authorized, or Council for a
consequential competing approach when its Herdr prerequisites are satisfied.
Select only relevant guidance and resources. Humanizer requires an explicit prose
editing request; it never applies to code or structured tool arguments.

Honor the user's host preference. Use an available Orca capability for Orca state;
Herdr requires a confirmed managed Herdr session. Read the installed host guide
before host operations. Missing tools are a limit to report, not a reason to install
plugins or alter global configuration automatically.

Preserve existing edits and authorization boundaries. Commit, push, deployment and
external changes require authorization for that action. Use proportionate checks;
installation tests cover this environment, not application quality or live services.
